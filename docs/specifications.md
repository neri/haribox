## 1. 仕様確認リスト

以下は実装時の確認項目。各項目が仕様を満たしていることを検証。

### 1.1 基本ウィンドウ機能

- 各ウィンドウが UUIDv4 形式の固有 windowId を持つ
- 各ウィンドウがアプリID（appId）をウィンドウモデルに保持する
- Terminal ウィンドウの appId が `f9c271dc-49ee-4295-811a-dc2bf7bd27a7` である
- Canvas ウィンドウの appId が `8faf5f5e-66ee-4580-8a8f-fe64ed78ea23` である
- File Manager ウィンドウの appId が `c1a107bb-20ec-4d3d-ad94-944d5bce863d` である
- About ウィンドウの appId が `88a37a04-c8e5-42e6-9f13-2f7fd31f62c3` である
- Text Viewer ウィンドウの appId が `e97b8139-cebf-40cd-8805-a0b87192c50f` である
- Onboarding ウィンドウの appId が `d1b3e8f4-7a2e-4c9d-b5f1-9a8c6d2e4f3b` である
- 各ウィンドウがユニーク ID を持つ
- 背面ウィンドウをタップすると最前面になる
- タイトルバーのドラッグでウィンドウ位置が変わる
- 閉じるボタンで対象ウィンドウが削除される
- ウィンドウがデスクトップ外へはみ出す場合、デスクトップ内へ収納される
- ウィンドウを移動する際、ウィンドウの位置情報がメモリに保持される
- ウィンドウが最前面化されるときに、z-index が最大値に更新される
- ウィンドウがクローズされるとき、該当ウィンドウを参照していた状態がクリーンアップされる

### 1.2 画面レイアウト

- 起動時に青緑デスクトップと下部タスクバーが表示される
- タスクバー左端にハンバーガーメニューボタンが表示される
- タスクバーの時計が現在時刻を表示し、定期更新される

### 1.3 スタートメニュー

- ハンバーガーメニューボタン押下でメニューが表示される
- メニュー表示中に再度ボタン押下でメニューがクローズされる
- メニュー外部をクリックするとメニューがクローズされる
- ESC キー押下でメニューがクローズされる
- メニュー内の「ターミナル」をクリックすると端末ウィンドウが新規作成される
- 新規端末作成後、メニューが自動的にクローズされる
- メニュー内の「ファイル」をクリックするとファイルマネージャウィンドウが起動される
- メニュー内に「About...」が表示される
- 起動時にはメニューが表示されていない (`isMenuOpen = false`)
- メニューポップアップはウィンドウより前面に配置される

### 1.4 端末ウィンドウ

- 新規端末ウィンドウは左上(40, 40)の位置に表示される
- 複数の端末ウィンドウを作成する際、毎回24pxずつ右下にカスケード配置される
- 端末ウィンドウ生成直後、入力テキストボックスがフォーカスされる
- 入力テキストボックスと実行ボタンがマウスクリックで操作できる
- 端末画面は白地黒文字で、出力増加時に自動スクロールする
- Enter または実行ボタンでコマンド実行後、入力テキストボックスがクリアされる
- 端末ウィンドウでの複数行入力を適切に処理する（改行コード処理）
- 端末出力がバッファサイズを超えた場合のスクロール処理

### 1.5 ターミナルコマンド

- `VER` 実行でアプリバージョンと git ハッシュが表示される
- `ECHO` 実行で入力パラメータがそのまま表示される
- `DIR/TYPE/COPY/DEL/REN/CLS` が仕様どおり動作する
- `HELP` コマンド実行で選定されたコマンド（VER, DIR, TYPE, NCST）の説明が表示される
- `EXIT` コマンド実行時に実行した端末ウィンドウが閉じられる
- `SET <name>=<value>` で環境変数が設定される
- `SET <name>` で環境変数の現在値が表示される
- `DIR` コマンド実行時にファイル一覧が表示される
- `LS` コマンド実行時にファイル一覧が表示される（`DIR` のエイリアス）
- `START <filename> [args...]` および `NCST <filename> [args...]` および `OPEN <filename> [args...]` コマンド実行時、ダミーターミナルでタスクが起動される
  - タスク出力がターミナルに表示されない
  - デフォルトターミナルへのフォールバック出力も発生しない
  - 起動エラーは `console.error` にのみ出力される
  - コマンドライン引数として「START」「NCST」「OPEN」を含まず、ファイル名以降のみが渡される
  - `OPEN` は `START` / `NCST` のエイリアス
- 定義済み以外のコマンド入力時、先頭トークンが既存ファイル名なら Worker が起動される
- ファイルもコマンドも見つからない場合、「Bad command or file name」が表示される
- 環境変数 `PATH_EXT` の初期値は `.hrb` である
- 未定義コマンド実行時、先頭トークンに `PATH_EXT` の拡張子を追加したファイルが検索される
- `PATH_EXT` は `:` で区切られた拡張子リスト形式である

### 1.6 ターミナルコマンド履歴機能

- ターミナルウィンドウごとに独立したコマンド履歴が保持される
- 上キー（ArrowUp）で古いコマンドを呼び出せる
- 下キー（ArrowDown）で新しいコマンドを呼び出せる、または入力中のテキストに戻せる
- 入力途中のコマンドがある状態で履歴を呼び出すと、入力テキストが一時保存される
- 履歴ブラウズ中に下キーで最後の位置に戻ると、保存された入力テキストが復元される
- コマンドを実行すると一時保存したテキストはクリアされる
- 他の履歴コマンドを実行すると保存テキストはクリアされる
- ウィンドウクローズ時に履歴と保存テキストがクリアされる
- 永続化されない（セッション中のみ保持）
- 同じコマンドを複数回実行した場合、古い履歴が削除され最新のみが保持される（重複排除）
- 複数ターミナルが開いている場合、各ターミナルの履歴は独立している
- ターミナルウィンドウ生成時の初期化コマンド（`VER`）は履歴に残らない

### 1.7 ファイルマネージャウィンドウ

- ファイルマネージャウィンドウの初期位置はデスクトップ右上（右端から20px、上端から40px）である
- ファイルマネージャウィンドウを移動してからクローズした場合、メモリ内にその位置が記憶される
- ファイルマネージャウィンドウを再度開いた場合、前回のセッション内での最後の位置に復元される
- ページリロード時には、ファイルマネージャウィンドウの位置記憶がリセットされ、右上初期位置に戻る
- ファイルマネージャウィンドウは同一フォルダの別ウィンドウを起動しない（最前面化）
- ファイルマネージャはファイルシステムのすべてのファイルを一覧表示する（ファイル名の先頭にアイコンを表示）
- ファイルマネージャで最初の端末がデフォルト端末に設定される
- 最初の端末を閉じると、次の端末がデフォルト端末に昇格する
- すべての端末が閉じると、デフォルト端末は null 状態（エラーにならず無言）
- 端末が 1 個のみ存在する場合、その端末がデフォルト端末として使用される
- ファイルマネージャでファイルをカーソルキーで選択できる
- ファイルマネージャでファイルをマウスクリックで選択できる
- ファイルマネージャでウィンドウフォーカスを切り替えても選択状態を維持する
- ファイルマネージャのアクティブウィンドウ内の選択項目背景色は青 (#0b5ed7) に白文字
- ファイルマネージャの非アクティブウィンドウ内の選択項目背景色はグレー (#c0c0c0) に黒文字
- ファイルマネージャのスクロール位置はウィンドウフォーカス切替時に保持される
- ファイルマネージャで Enter キーまたはダブルクリックでファイル実行
- ファイルマネージャ内のファイルリストは、ファイルシステムの変更を検知して自動更新される
- ファイルマネージャでのキー入力が他のウィンドウに伝播しない
- ファイルマネージャは他のウィンドウでのファイル操作を監視して自動更新する
- 複数 Worker 同時実行時、ファイルマネージャに最新のファイル一覧が反映される

### 1.8 ファイル実行

- `PATH_EXT` に含まれる拡張子のファイルをファイルマネージャで実行すると Worker が起動される
- `.txt` ファイルをファイルマネージャで実行すると、`tview` ファイルが PATH_EXT で検索されて `tview -w80 -h24 <filename>` コマンドが実行される
- `.bmp` または `.jpg` ファイルをファイルマネージャで実行すると、`gview` ファイルが PATH_EXT で検索されて `gview <filename>` コマンドが実行される
- `.mml` ファイルをファイルマネージャで実行すると、AudioContext を resume した後、`mmlplay` ファイルが PATH_EXT で検索されて `mmlplay <filename>` コマンドが実行される
- 実行不可ファイルをファイルマネージャで実行するとエラーダイアログが表示される

### 1.9 ファイルアイコン

- 画像ファイル（`.bmp`, `.jpg`）のアイコンは `photo.svg` で表示される
- 音楽ファイル（`.mml`）のアイコンは `file-music.svg` で表示される
- ウィンドウタイトルバーの左端にアイコンが表示される
- ターミナルウィンドウのタイトルバーアイコンは `terminal-2` である
- テキストビューアのタイトルバーアイコンは `file-text` である
- ファイルマネージャのタイトルバーアイコンは `folder` である
- About ウィンドウのタイトルバーアイコンは `category` である
- Rust タスクウィンドウのタイトルバーアイコンは `app-window` である
- アクティブウィンドウのタイトルバーアイコン色は白 (#fff) である
- 非アクティブウィンドウのタイトルバーアイコン色は黒 (#111) である

### 1.10 About ウィンドウ

- About... 選択時に About ウィンドウが表示される
- About ウィンドウに「About」タイトルが表示される
- About ウィンドウにアプリ名、バージョン、Git ハッシュが別行で表示される
- About ウィンドウにライセンス文が HTML レンダリングで表示される（Markdown太字形式 `**text**` 対応）
- About ウィンドウのライセンス文がオーバーフロー時はスクロール可能
- About ウィンドウの OK ボタン押下でウィンドウがクローズされる
- About ウィンドウが既に表示されている場合、再度開こうとすると最前面化される

### 1.11 テキストビューアウィンドウ

- ファイルマネージャでテキストファイル（`.txt`）を実行すると、`tview` ファイルが PATH_EXT で検索されて `tview -w80 -h24 <filename>` コマンドが実行される
- テキストビューアウィンドウはファイル名をタイトルとして表示する
- テキストビューアのテキストボックスは読み取り専用である
- テキストビューアのテキストボックスは複数行表示可能でスクロール可能である
- テキストビューアのデフォルトサイズは 600px × 400px である
- テキストビューアは複数ウィンドウ開始時にカスケード配置される
- テキストビューアウィンドウは同一ファイルでも複数開くことが可能である
- テキストビューアの内容は UTF-8 でデコードされる
- テキストビューアで UTF-8 デコード失敗時はエラーダイアログが表示される
- テキストビューアウィンドウのタイプは `textviewer` である
- テキストビューアのテキストボックスをクリックするとウィンドウがアクティブ化される
- テキストビューアのスクロール位置はウィンドウフォーカス切替時に保持される

### 1.12 Onboarding ウィンドウ

- アプリケーション初期化時に Onboarding ウィンドウが自動生成される
- Onboarding ウィンドウのサイズが幅 640px × 高さ 546px である（背景 514px + タイトルバー 32px）
- Onboarding ウィンドウが画面中央に配置される
- 背景画像 `src/assets/bliss.png` が表示される
- 具体的な文言・機能紹介・ヒント・ボタン表示はテスト対象外とする（人間による保守対象）
- Onboarding 内の操作でウィンドウをクローズできる
- Onboarding ウィンドウがクローズ時に状態がクリーンアップされる

### 1.13 ファイルシステム

- デスクトップへの drag&drop でファイルが取り込まれる
- 取り込み時に既存ファイルと取り込みデータのバイナリサイズ合計が `1.5MiB` (`1,572,864` bytes) を超える場合、エラーダイアログで表示して取り込みを中止する
- 取り込み失敗時にエラーメッセージがダイアログで表示される
- 取り込み失敗時に既存ファイルシステムが変更されない
- localStorage に保存データが存在する場合は起動時に復元し、存在しない場合はビルド時初期ファイル群を読み込む
- ファイルアクセスが大文字小文字非依存である (`ABC == abc == Abc`)
- ファイル名表示は入力時の大文字小文字を保持する
- デフォルト端末への不明なメッセージ出力は受け付けない（エラーにならない）

### 1.14 ファイルシステム永続化

- 各ファイルは内部的に `isInitialFile` フラグを保持する
- 初期ファイルは localStorage に保存されない
- ドラッグアンドドロップで取り込んだファイルのみ localStorage に保存される
- 実行時に新規生成したファイルのみ localStorage に保存される
- 起動時に初期ファイル群でファイルシステムを初期化する
- 起動時に localStorage から保存データを読み込み、初期ファイルシステムにマージする
- localStorage のマージ時に同名ファイルが存在する場合、localStorage のデータで上書きされる
- 初期ファイルと同じ名前のファイルをドラッグアンドドロップで取り込んだ場合、`isInitialFile` フラグが `false` に変更される
- 初期ファイルと同じ名前のファイルを実行時生成した場合、`isInitialFile` フラグが `false` に変更される
- 初期ファイルと同じ名前で上書きされたファイルは次回起動時に localStorage から復元される
- 初期ファイルをセッション内で削除した場合、その情報は localStorage に保存されない
- ブラウザ再読み込み後、削除した初期ファイルが復活する
- localStorage の保存データは `isInitialFile === false` のファイルのみ含める

### 1.15 Rust/Wasm連携

- 端末コマンド経由で Rust(Wasm) が Worker 上で実行される
- Rust 側が指定したウィンドウサイズとタイトルでウィンドウが生成される
- UI の `windowId` は UUIDv4 である
- Rust 側で扱う windowId は数値ハンドルで、Worker が UI UUID へ変換する
- `open_window` の戻り値として Rust 側へ返るのは数値ハンドルである
- Rust 側から戻り値の数値ハンドル指定でウィンドウ操作インターフェースを呼べる
- Rust 側から Canvas imageData 一括描画インターフェースを呼べる
- Rust タスクウィンドウの内容領域が Canvas である
- 上記 Worker 起動時に `terminalWindowId`・`fileName`・`commandLine` が引数として渡される
- Worker の起動は `startWithCommand` のみで、起動引数が必須である
- Worker が `println` / `print` インターフェースで指定端末へデバッグ出力できる
- Worker 実行中のメッセージ処理が非ブロッキングで実行される

### 1.16 複数Worker対応

- Main がファイルシステムを一元管理する
- 複数 Worker が同時実行時、各 Worker は Main から最新スナップショットを受け取る
- Worker が `js_write_file` で書き込みを実施すると、Main が全 Worker へ `updateFileSystemSnapshot` メッセージを配信する
- Worker が スナップショット更新メッセージを受け取ると、内部の fileSystem が最新化される
- 複数 Worker 実行時、一方の Worker の書き込み内容が、他方の Worker で読み込める
- ファイル書き込み後の `persistFileSystem()` は Main でのみ実行される
- localStorage への永続化は原子的に実行される（二重書き込みなし）
- 複数 Worker 実行時、ファイルシステム更新メッセージに `isInitialFile` フラグが含まれる

### 1.17 タスクバーウィンドウ一覧機能

- タスクバーにウィンドウボタングループ領域が配置される（ハンバーガーメニューと時計の間）
- ウィンドウ作成時にタスクバーにボタンが追加される
- ウィンドウ削除時にタスクバーのボタンが削除される
- 同じタイプのウィンドウが複数ある場合、1 つのグループボタンで表示される
- グループボタン表示形式は `[タイプ名] ×個数` である
- Canvas ウィンドウは個別表示される（グループ化されない）
- グループボタンをクリックするとドロップダウンメニューが表示される
- ドロップダウンメニュー内の個別ウィンドウをクリックするとそのウィンドウが前面化される
- ドロップダウン外をクリックするとすべてのドロップダウンが閉じられる
- ウィンドウタイトル変更時にボタンテキストが更新される
- アクティブウィンドウのボタンは背景が青色 (#0b5ed7)、文字が白 (#fff) で表示される
- 非アクティブウィンドウのボタンはデフォルトスタイルで表示される
- ボタンホバー時に背景が薄い灰色 (#e9ecef) で表示される
- グループボタン内のウィンドウがアクティブな場合、グループボタン自体もハイライト表示される
- `windowGroups` は ウィンドウ操作（作成・削除）時に再計算される
- `WindowGroupInfo` は `appId`、`kind`、`windowIds`、`isExpanded` を保持する

## 2. テスト基準

### 2.1 アクティブウィンドウシステムのテスト基準

- ウィンドウをクリックするとそのウィンドウがアクティブ化される
- アクティブウィンドウのタイトルバーが青色 (#0b5ed7) で表示される
- 非アクティブウィンドウのタイトルバーが灰色で表示される
- アクティブなファイルマネージャのリストボーダーが2px青色で表示される
- 非アクティブなファイルマネージャのリストボーダーが灰色で表示される
- ファイルマネージャがアクティブな場合のみ矢印キー（上下）が動作する
- ファイルマネージャがアクティブな場合のみ Enter キーが動作する
- ファイルマネージャが非アクティブな場合、矢印キーを押しても無反応
- ファイルマネージャをクリックするとアクティブになり、フォーカスが移動する
- 他のウィンドウがアクティブな場合、ファイルマネージャのキー操作は受け付けない
- 複数ウィンドウ表示時に、各ウィンドウが個別にアクティブ化・非アクティブ化できる

### 2.2 非機能要件

- マウス/タッチの双方で操作できる実装を推奨
- 画面リサイズ時にも破綻しないレイアウト
- 単一ページ遷移なしで操作継続
