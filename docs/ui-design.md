## 1. 画面構成

### 1.1 全体レイアウト

- 画面全体を 2 領域で構成する。
- 上側: デスクトップ領域 (可変高)
- 下側: タスクバー領域 (固定高)

### 1.2 デスクトップ領域

- 背景色: `#00a9a9` (Windows 95/98 風の明るいティール、CSS変数 `--desktop-bg` で定義)
- ウィンドウを複数重ねて表示
- ウィンドウはデスクトップ外にはみ出した位置でも描画可能

### 1.3 タスクバー領域

- 高さ: `48px` (下側固定)
- レイアウト: 左側 → 中央 → 右側の 3 領域で構成
  - 左側: ハンバーガーメニューボタン
  - 中央: ウィンドウボタングループ領域（タスクバーウィンドウ一覧表示）
  - 右側: ボリュームコントロール + 時計表示
- ウィンドウボタンは開いているウィンドウの情報をアイコン + タイトルで表示
- グループ化：複数の同一タイプのウィンドウは 1 つのグループボタンとして集約表示
  - ホバー時またはクリック時にドロップダウンで個別ウィンドウ一覧を表示
  - Rust Task (Canvas) は個別表示（グループ化しない）

### 1.4 スタートメニュー

タスクバー左端のハンバーガーメニューボタンを「スタートメニュー」と定義する。

- **スタートメニューボタン**:
  - アイコン: `src/assets/icons/box-multiple.svg`
  - ボタン押下でメニューポップアップが表示
  - メニューはボタンの上側に表示される
  - メニュー外部をクリック、または ESC キー押下でメニューをクローズ
  - メニューはウィンドウより前面に配置

- **スタートメニュー項目**:
  - 各項目には、起動するウィンドウと同じアイコンを表示する
  - ターミナル: `src/assets/icons/terminal-2.svg` 新規端末ウィンドウを作成
  - ファイル: `src/assets/icons/folder.svg` ファイルマネージャウィンドウを起動
  - About...: `src/assets/icons/category.svg` About ウィンドウを表示

### 1.5 ボリュームコントロール

タスクバー右側に配置される音量調整UI。デスクトップ内で実行されるRust/Wasm アプリケーションによる音声出力を制御する。

**基本構成:**
- ボリュームボタン: タスクバー右側に配置、ステータスアイコン表示
- ボリュームポップアップ: ボタン上に表示される音量調整パネル
  - 位置: ボタンの上側に表示（タスクバーの上方向）
  - ボリュームポップアップ外部をクリック、または ESC キー押下でクローズ
  - ウィンドウより前面に配置

**ボリュームボタン仕様:**
- 大きさ: 24×24px
- ボタン押下でポップアップの表示/非表示をトグル
- アイコン表示: 以下のいずれかに応じて選択

| 状態 | 表示アイコン | 説明 |
|------|-------------|------|
| AudioContext suspended | volume-3.svg (X) | AudioContext がまだアクティベーションされていない状態 |
| ボリューム 0% | volume-3.svg (X) | 完全ミュート状態 |
| ボリューム 1～29% | volume-4.svg (小) | 小さい音量 |
| ボリューム 30～69% | volume-2.svg (中) | 中程度の音量 |
| ボリューム 70～100% | volume.svg (大) | 大きい音量 |

**ボリュームポップアップ仕様:**
- 幅: 240px
- 構成: 上部に数値表示、下部にスライダーと音量アイコン
  - 数値表示: 現在のボリューム値を 0～100 の整数で表示（太字）
  - スライダー: HTML5 range input（0～100）
  - アイコン: スライダー両側にボリュームアイコン（視認性向上）

**ボリューム保存:**
- ボリューム変更時に `localStorage` キー `'haribote.audio.volume'` に 0.0～1.0 の実数値で保存
- アプリ起動時に localStorage から復元、保存されたボリュームで初期化
- localStorage にキーが存在しない場合は初期値 0.5 で初期化

**Web Audio API との連携:**
- 初回ユーザー操作時に AudioContext を `resume()` で実行状態に遷移（必須）
- ボリュームボタン押下でも AudioContext の resume を試行
- MMLファイル実行時にも AudioContext の resume を試行
- GainNode を介して全Oscillator のゲインを統一制御
- Oscillator 生成時は初期ゲイン 0.3 で制限（クリッピング防止）

### 1.6 タスクバーウィンドウボタン

**ウィンドウボタングループの表示**:
- タスクバー中央領域にウィンドウボタンを配置
- 各ボタンはウィンドウのアイコンとタイトルを表示
- ボタンサイズ: アイコン 16x16px + パディング + タイトルテキスト + パディング
- タイトルは必要に応じて短縮（画面幅に応じて制限）
- アクティブウィンドウのボタンは異なるスタイル（背景色など）で表示

**グループ化仕様**:

| ウィンドウタイプ | グループ化 | アイコン |
|------------------|-----------|----------|
| `terminal` | ○ グループ化 | terminal-2.svg |
| `filemanager` | ○ グループ化 | folder.svg |
| `about` | ○ グループ化 | category.svg |
| `textviewer` | ○ グループ化 | file-text.svg |
| `canvas` | ✕ 個別表示 | app-window.svg |

- グループ化された複数ウィンドウ表示時のボタン形式:
  - グループボタン例: `[Terminal] ×2` (タイプ名 + 個数)
  - グループをホバーまたはクリックするとドロップダウンで個別ウィンドウ一覧を表示
  - ドロップダウン内の各項目をクリックすると対応ウィンドウをアクティブ化して前面表示
- Canvas ウィンドウは個別表示（グループ化なし）

**ボタン操作**:
- ボタンクリック:
  - グループボタン: ドロップダウンを表示/非表示
  - 個別ボタン: 該当ウィンドウをアクティブ化して前面表示
  - 既にアクティブなウィンドウのボタン再クリック: ウィンドウを最小化（非表示）※将来機能
- ボタンホバー: グループボタンの場合、ドロップダウンを表示

**更新タイミング**:
- ウィンドウ作成時: 対応するボタンを追加
- ウィンドウ削除時: 対応するボタンを削除
- ウィンドウタイトル変更時: ボタンテキストを更新
- ウィンドウアクティブ状態変化時: ボタンのスタイルを更新
- 若干の遅延は許容（イベント駆動または定期更新）

### 1.7 メッセージ表示言語

- **ダイアログ表示**：日本語を使用
  - ファイル取り込みサイズ超過時: 「ファイルの取り込みに失敗しました: 合計サイズ (X.XX MiB + Y.YY MiB) が 1.5 MiB の制限を超えています」
  - ファイル実行不可: 「このファイルは実行できません: filename」
- **ターミナル出力（成功メッセージ）**：英語を使用
  - ファイル取り込み成功: 「Imported filename (XXX KB)」

## 2. ウィンドウ仕様

### 2.1 構造

```
+-----------------------------------+
| <アイコン> <タイトル> (パディング) <閉じるボタン> |
+-----------------------------------+
| <ウィンドウの内容>                   |
+-----------------------------------+
```

- 枠線: 1px solid black
- タイトルバー: HTML 要素で描画
- タイトルバー左端: ウィンドウタイプに応じたアイコン（16x16px）
  - アイコン色：タイトルバー文字色と同一
  - アクティブ時: 白色 (#fff)
  - 非アクティブ時: 黒色 (#111)
- タイトルバー右端: クローズボタン
  - アイコン: `src/assets/icons/x.svg`（16x16px）
  - アイコン色：タイトルバー文字色と同一

### 2.2 ウィンドウ種別と初期仕様

各ウィンドウタイプの基本仕様は以下の通り。詳細は 2.5 を参照。

### 2.3 識別子

#### 2.3.1 ウィンドウID

- 各ウィンドウ生成時にユニーク ID を採番
- ID をキーとして以下を実施
  - 前面化
  - 移動
  - クローズ

#### 2.3.2 アプリID

- 各アプリケーションタイプに固有の UUIDv4 を割り当て、アプリケーション種別を識別
- ウィンドウタイプと一対一対応
- 用途：
  - ウィンドウタイプの分類・管理
  - ローカルストレージのキー体系（将来拡張時）
  - ウィンドウルールの適用判定（例: 1 個限定ウィンドウかどうか）

**各アプリのアプリID:**
- Terminal: `f9c271dc-49ee-4295-811a-dc2bf7bd27a7`
- Rust Task (Canvas): `8faf5f5e-66ee-4580-8a8f-fe64ed78ea23`
- File Manager: `c1a107bb-20ec-4d3d-ad94-944d5bce863d`
- About: `88a37a04-c8e5-42e6-9f13-2f7fd31f62c3`
- Text Viewer: `e97b8139-cebf-40cd-8805-a0b87192c50f`
- Onboarding: `d1b3e8f4-7a2e-4c9d-b5f1-9a8c6d2e4f3b`

注記:
- UI で扱う `windowId` は UUIDv4 文字列を採用する。
- Rust 側では Wasm 境界の簡潔性のため数値ハンドルを使用し、Worker 内で `Rust数値ID <-> UI UUID` を変換する。

### 2.4 ウィンドウの挙動

#### 2.4.1 新規作成

- 新規端末ボタン押下時、端末ウィンドウを追加
- 端末生成直後、自動的に `VER` コマンドを内部実行してアプリバージョンを表示
  - 入力行（`>` プロンプト）は表示されない
  - VER の実行結果のみが画面に表示される
- VER 実行後、入力テキストボックスへフォーカス

#### 2.4.2 前面化とアクティブ化

- ウィンドウ内任意領域タップ時、他ウィンドウより背面であれば最前面へ移動
- ウィンドウがクリックされた場合、そのウィンドウがアクティブになる
- 入力テキストボックスや実行ボタンなど操作要素のクリックでは、フォーカス阻害を防ぐため前面化起因の再描画を行わない
- **コマンド入力欄のタップ挙動** (ターミナルウィンドウ):
  - ターミナルが非アクティブなときにコマンド入力欄をタップした場合、ウィンドウをアクティブにしてコマンド入力欄にフォーカスを移動する

#### 2.4.3 キーボード入力とアクティブ化

- ウィンドウ内のサブアプリケーションのキーボード操作は、そのウィンドウがアクティブな場合のみ受け付ける
- ターミナルウィンドウ: コマンド入力がアクティブな場合のみ動作
- ファイルマネージャウィンドウ: 矢印キー（上下）、Enter キーがアクティブな場合のみ動作
- **ビジュアル表現** (アクティブウィンドウ):
  - タイトルバー背景色: 青色 (#0b5ed7)
  - タイトルバーテキスト色: 白 (#fff)
  - 主ボタン（実行ボタン、OKボタンなど）: 青地 (#0b5ed7) に白文字
- **ビジュアル表現** (非アクティブウィンドウ):
  - タイトルバー背景色: 灰色 (#c0c0c0)
  - タイトルバーテキスト色: 黒 (#111)
  - 主ボタン: 灰色地 (#c0c0c0) に黒文字

#### 2.4.4 移動

- タイトルバーをドラッグすると位置変更
- ドラッグ中にポインタがデスクトップ外へ出た場合、ポインタ座標をデスクトップ境界でクリップし、それ以上外側へ移動しない
- 上方向へ移動する際、ウィンドウの `y` は 0 未満にならない

#### 2.4.5 閉じる

- クローズボタン押下で対象ウィンドウのみ削除
- クローズボタン表示形式:
  - Vite の `?raw` インポートで SVG (`src/assets/icons/x.svg`) をインライン展開

### 2.5 ウィンドウ種別別仕様

#### 2.5.1 端末ウィンドウ

**基本情報:**
- タイプ: `terminal`
- タイトル: `'Terminal'`
- アイコン: `src/assets/icons/terminal-2.svg`
- 生成方法: タスクバーの新規端末ボタン
- インスタンス: 複数可

**レイアウト:**
```
+-----------------------------------+
| <タイトル> (パディング) <閉じるボタン> |
+-----------------------------------+
| <ターミナル画面>                 |
+-----------------------------------+
| <コマンド入力テキスト>    <実行ボタン> |
+-----------------------------------+
```

**仕様:**
- ターミナル画面は白地ダークグレー文字
- 文字が下端を超えたら自動スクロール
- **スクロールバッファ管理:**
  - スクロールバッファの最大行数: 4000 行（定数 `TERMINAL_MAX_LINES` で管理）
  - 上限を超えた場合は古い行から自動削除
  - テキストに改行文字（`\n`）が含まれる場合は別行として挿入
- **コマンド履歴機能:**
  - ターミナルウィンドウごとに独立したコマンド履歴を管理
  - 履歴は永続化されず、セッション中のみ保持
  - **上キー（ArrowUp）**：古いコマンドを履歴から呼び出す
  - **下キー（ArrowDown）**：新しいコマンドを履歴から呼び出す、最後は入力中のコマンドに戻る
  - **入力途中のテキスト保存**：履歴ブラウズ開始時に現在の入力を保存し、ブラウズ後に復元可能
  - **重複排除**：同じコマンドを再実行した場合、古い履歴を削除して新しいものを先頭に追加
  - **初期化コマンド除外**：ターミナルウィンドウ生成時に自動実行される `VER` コマンドは履歴に残らない
- ウィンドウ生成直後、初期化メッセージを表示せず、自動的に `VER` コマンドを実行
- ユーザが入力したコマンドの実行により出力が画面に表示される
- 定義済みコマンド：VER, ECHO, CLS, DIR, TYPE, COPY, DEL, REN, SET, HELP, START, NCST
- 未定義コマンドはファイル実行として処理
- ウィンドウをクローズすると、そのウィンドウの履歴はクリアされる

#### 2.5.2 Rust タスクウィンドウ（Canvas）

**基本情報:**
- タイプ: `canvas`
- タイトル: タスク定義
- アイコン: `src/assets/icons/app-window.svg` (デフォルト)
- 生成方法: 端末コマンド経由で Worker + Rust(Wasm) により生成
- インスタンス: 複数可

**仕様:**
- コンテンツ領域は Canvas 要素
- ウィンドウサイズとタイトルは Rust 側で指定
- Canvas への描画は Rust 側が `js_draw_image` インターフェースで実施

**キーボード入力ハンドリング:**
- Canvas ウィンドウがアクティブ（フォーカス）な時、すべてのキーボード入力イベント（keydown/keyup）を対応する Worker に転送
- Main スレッドで `document.addEventListener('keydown/keyup', ...)` で捕捉
- アクティブウィンドウが Canvas 型かつ `workerByWindowId` に登録されている場合、`keyboardEvent` メッセージを Worker に `postMessage`
- Worker は `keydown` をイベントコードへ変換してグローバルイベントキューに追加し、Rust 側は `js_get_keyboard_event()` で取得する
- `keyup` はWorkerへ転送するが、イベントキューには追加しない
- 特殊キー・修飾キーを含むイベントコードの詳細は [Rust/Wasmインターフェース](./rust-wasm-interface.md) を正本とする
- Canvas ウィンドウ以外がアクティブの場合、キーボード入力は転送されない

#### 2.5.3 ファイルマネージャウィンドウ

**基本情報:**
- タイプ: `filemanager`
- タイトル: `'File System'`
- アイコン: `src/assets/icons/folder.svg`
- 生成方法: ハンバーガーメニューの「ファイル」から起動
- インスタンス: 1個限定（既に起動済みの場合は最前面化）

**初期位置と位置記憶:**
- **初期位置**: デスクトップ右上（右端から20px、上端から40px）
- **位置記憶**: ウィンドウをドラッグで移動させた場合、クローズ時にその位置をメモリに保持
  - メモリ内でのみ保持（localStorage には保存しない）
  - ページリロード時にはリセットされ、右上の初期位置に戻る
  - 再度開くと、前回のセッション内での最後の位置に復元される

**ファイル一覧表示:**
- ファイルシステムのすべてのファイルを一覧表示
- ファイル名の先頭にアイコンを表示（拡張子に基づいて異なるアイコン）

**ファイル選択:**
- カーソルキー (上下矢印) またはマウスクリックでファイルを選択
- 選択されたファイルはハイライト表示
- **ウィンドウフォーカス切替時に選択状態を保持する**
- **選択項目の背景色**:
  - ウィンドウがアクティブな場合: 青 (#0b5ed7) に白文字
  - ウィンドウが非アクティブな場合: グレー (#c0c0c0) に黒文字

**スクロール位置保持:**
- ファイルマネージャーのスクロール位置をメモリに保持
- ウィンドウ間でフォーカスを切り替えてもスクロール位置は復元される
- ウィンドウをクローズするとスクロール位置情報はクリーンアップされる

**ファイル実行/オープン:**
- 選択ファイルで Enter キー押下またはダブルクリック時、以下の処理を実行:
  - 拡張子が環境変数 `PATH_EXT` に含まれる場合:
    - Rust Task を起動（`start <filename>`）
  - 拡張子が `.bmp` または `.jpg` の場合（大文字小文字不区別）:
    - `gview` ファイルをファイルシステムから検索
      - 直接 `gview` という名前で検索
      - 見つからない場合、`gview` + PATH_EXT の各拡張子（例：`gview.hrb`）で検索
    - 見つかった場合、Rust Task のコマンド `gview <filename>` を実行
    - 見つからない場合、エラーダイアログ「このファイルは実行できません: gview」を表示
  - 拡張子が `.txt` の場合:
    - `tview` ファイルをファイルシステムから検索
      - 直接 `tview` という名前で検索
      - 見つからない場合、`tview` + PATH_EXT の各拡張子（例：`tview.hrb`）で検索
    - 見つかった場合、Rust Task のコマンド `tview -w80 -h24 <filename>` を実行
    - 見つからない場合、エラーダイアログ「このファイルは実行できません: tview」を表示
  - 拡張子が `.mml` の場合（大文字小文字不区別）:
    - `mmlplay` ファイルをファイルシステムから検索
      - 直接 `mmlplay` という名前で検索
      - 見つからない場合、`mmlplay` + PATH_EXT の各拡張子（例：`mmlplay.hrb`）で検索
    - 見つかった場合、Rust Task のコマンド `mmlplay <filename>` を実行
    - 見つからない場合、エラーダイアログ「このファイルは実行できません: mmlplay」を表示
  - 上記いずれにも該当しない場合:
    - エラーダイアログ「このファイルは実行できません: filename」を表示

**ファイルシステム監視:**
- 他のウィンドウでのファイル作成・削除・リネームを監視
- 変更時に一覧を自動更新

#### 2.5.7 System Modal Dialog - Drag & Drop File Import

**基本情報:**
- タイプ: `systemmodal`
- 表示トリガー: ユーザーがファイルをデスクトップにドラッグ（dragover時にリスナーレベルで検出）
- 自動クローズ: ドラッグがウィンドウ外に完全に出た時（dragleave）または OK ボタン押下
- インスタンス: 1個限定
- タイトル: なし（タイトルバー非表示）

**ウィンドウ仕様:**
- デフォルトサイズ: 幅 480px × 高さ 280px
- 初期配置: ウィンドウサイズから計算してデスクトップ中央に配置
- Z-インデックス: 非常に高い値（maxZIndex + 100）で他ウィンドウを覆う

**操作モード:**

| モード | トリガー | 表示内容 | ボタン | 説明 |
|--------|---------|---------|--------|------|
| Mode 1 (Import) | dragover(初回) | "ここにファイルをドロップすると取り込めます。" | なし | ドラッグ中の待機状態 |
| Mode 2 (Complete) | drop後 | 成功: "{filename} を取り込みました。" | OK ボタン | ファイル取込成功 |
| Mode 2 (Error) | drop後 | エラー: "取り込みに失敗しました: {詳細}" | OK ボタン | ファイル取込エラー |

**オーバーレイ:**
- 全画面を覆う半透明の暗い背景（rgba(0,0,0,0.5)）
- backdrop-filter: blur(2px) でデスクトップをぼかす
- オーバーレイはポインタイベントをすべてキャッチし、背後のウィンドウへの操作を防止

**モーダルフレーム:**
- 背景色: 白（#ffffff）
- 角丸: border-radius 12px
- 影: box-shadow で立体感を表現
- クローズボタン: 右上隅に 32×32px の × ボタン配置

**コンテンツレイアウト:**
```
+---------------------------------------------+
| <クローズボタン (×)>                      |
| +---------------------------------------+   |
| |  "ここにファイルをドロップすると      |   |
| |   取り込めます。"                    |   |
| |                      <OK ボタン>      |   |
| +---------------------------------------+   |
+---------------------------------------------+
```

**ファイル取込の流れ:**

1. **dragenter**: ユーザーがファイルをデスクトップ上にドラッグ開始
   - 初期状態のリセット：Modal の再作成フラグをリセット
   - イベント処理継続準備

2. **dragover**: ドラッグ継続中（複数回発火）
   - Modal が作成されていない、または前回のドラッグで閉じられていればNew Modal を Mode 1 で表示
   - dropEffect を 'copy' に設定（コピーカーソル表示）
   - 既存 Modal がある場合は再利用（重複作成を防止）

3. **drop**: ユーザーがファイルをドロップ
   - FileList を抽出して import 処理を非同期で実行
   - Modal は Mode 1 のまま表示（処理中）
   - 複数ドラッグ処理フラグをリセット

4. **Import 処理**:
   - 全ファイル（既存+新規）の総サイズを計算
   - 最大 1.5 MiB（1572864 バイト）を超過していないか確認
   - 制限超過時は MiB 単位で詳細エラーを返す例）"合計サイズ (0.19 MiB + 1.56 MiB) が 1.5 MiB の制限を超えています"
   - 制限内の場合、ファイルをファイルシステムに追加
   - Terminal に取込結果を出力："Imported {filename} ({size})"

5. **Modal 更新**:
   - 成功: Mode 2 で "{filename} を取り込みました。" を表示、OK ボタン表示
   - エラー: Mode 2 で "取り込みに失敗しました: {詳細エラー}" を表示、OK ボタン表示
   - File System ウィンドウが自動更新されて新ファイルが表示

6. **dragleave**: ドラッグがウィンドウ外に完全に出た
   - Modal が自動クローズ
   - ウィンドウ内での要素間移動による dragleave イベント（Mode 1 中）は無視
   - viewport の外に出た場合のみクローズ（clientX/clientY の範囲確認）

7. **OK ボタン**: Modal をクローズ

**スタイル:**

| クラス | 説明 |
|--------|------|
| `.system-modal-overlay` | 全画面オーバーレイ、半透明背景 + ぼかし |
| `.system-modal-frame` | モーダルのメインフレーム、白背景、角丸、影 |
| `.system-modal-close-button` | 右上のクローズボタン、×表記 |
| `.system-modal-message` | メッセージテキスト、中央配置、15-16px フォント |
| `.system-modal-message-import` | Mode 1 用のメッセージスタイル |
| `.system-modal-message-complete` | Mode 2 用のメッセージスタイル |
| `.system-modal-button` | OK ボタン、青背景（#0b5ed7）、ホバー・アクティブ状態 |
| `.system-modal-button-container` | ボタンコンテナ、フレックス行で右寄せ配置 |

**エラーメッセージの種類:**

| エラー状況 | メッセージ例 |
|----------|-----------|
| ファイルサイズ超過 | "取り込みに失敗しました: 合計サイズ (既存 MiB + 新規 MiB) が 1.5 MiB の制限を超えています" |
| ファイル読込失敗 | "取り込みに失敗しました: {詳細エラーメッセージ}" |
| ファイルシステム追加失敗 | "取り込みに失敗しました: {詳細エラーメッセージ}" |
| ファイルなし | "取り込み可能なファイルがありません" |

**実装ファイル:**
- `src/main.ts`:
  - `importDroppedFiles(files: FileList)`: ファイル取込処理（1.5 MiB チェック、MiB 単位エラー情報付き）
  - `createSystemModalWindow(mode: 'import' | 'complete')`: Modal 作成
  - `createSystemModalPanel(win: WindowModel)`: Modal コンテンツ
  - Window レベルのキャプチャフェーズリスナー: dragenter, dragleave, dragover, drop
  - `modalCreated`: ドラッグセッション中の Modal 作成状態フラグ
  - `systemModalModeByWindowId`: Mode 状態管理用 Map
- `src/style.css`: `.system-modal-*` クラス群
